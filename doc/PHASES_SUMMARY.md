## Текущий функционал (PHASE-04)

### ✅ Что работает:
- Создание ProcessInstance вручную через репозитории (с этапами/итерациями/участниками)
- Запуск процесса STANDARD: `ProcessService.startProcess()` → Draft → InProgress
- Активация первого этапа: Pending → Active
- Назначение задач участникам (Parallel — все Assigned, Sequential — первый Assigned, остальные Pending)
- Расчёт сроков: `startedAt`, `dueAt` этапа
- Аудит всех переходов: AuditEvent для каждого перехода
- Guards: IsInitiator, AllMandatorySlotsFilled, AllDurationsValid, PreviousStageCompleted
- Actions: SetStartedAt, AssignStageTasks, AssignParticipantTasks, SetStageStartedAt, CalcStageDueAt

### ❌ Что НЕ работает:
- Принятие решения участником — **нет DecisionService**
- Закрытие этапа после решений — **нет агрегации**
- Переход к следующему этапу — **нет ActivateNextStage**
- Завершение процесса — **процесс застревает в InProgress**
- Возврат на доработку — **нет OnRework/Resume**
- Создание процесса из шаблона — **нет MatchService/RouteGeneratorService**
- REST API — **ничего**
- Публикация событий — **только emits в TransitionResult, не уходит наружу**

## Следующие шаги

### Для продолжения разработки:

1. **Выбрать следующую фазу:** рекомендуется **PHASE-05** (Принятие решения участником)
2. **Cowork готовит детальный тикет:** `doc/tickets/PHASE-05-participant-decision.md` по шаблону
3. **Claude Code реализует:** в ветке `feature/phase-5-participant-decision`
4. **Тестирование:** интеграционный тест (ProcessService → DecisionService → participant.status = Decided)
5. **PR и ревью:** мерж в main после проверки Cowork

### Альтернативные приоритеты:

- **Если нужен MVP быстрее:** пропустить PHASE-10 (доп.согласующие) и PHASE-11 (замечания) до второго этапа
- **Если нужна демонстрация UI:** сделать PHASE-21 (REST API) раньше, но domain-логика будет неполной
- **Если критична интеграция:** сделать PHASE-19 (Event Publisher) сразу после PHASE-07

## 1. Назначение

Документ описывает два типа процессов, поддерживаемых модулем «Согласование»: **стандартный** и **единый**. Каждый тип решает свою задачу и имеет собственные характеристики, поведение и бизнес-правила.

**Зачем нужны разные типы:**
- Разные бизнес-сценарии требуют разной логики.
- Одни процессы — с итерациями и возвратами.
- Другие — с финальным решением ответственного.
- Модуль должен поддерживать оба.

## 2. Обзор типов процессов

| Тип | Назначение | Ключевая особенность |
|---|---|---|
| **STANDARD** | Классическое согласование | Итерации этапов, возврат на любой разрешённый этап |
| **UNIFIED** | Единый процесс | Финальное решение ответственного |

**Как выбирается:** задаётся в шаблоне маршрута.

## 3. Стандартный процесс (STANDARD)

### 3.1 Назначение

Классический процесс согласования с несколькими этапами и итерациями. Каждый этап — отдельный шаг с собственным набором решений.

### 3.2 Когда использовать

- Нужны итерации этапов.
- Нужны разные режимы агрегации на разных этапах.
- Нужна гибкость в порядке работы участников.
- Нужна возможность возврата на любой разрешённый этап.
- Итог определяется последним этапом.

### 3.3 Характеристики

| Свойство | Значение | Обоснование |
|---|---|---|
| Этапы | Несколько, последовательно | Классическая модель согласования |
| Участники этапа | Один или несколько | Гибкость |
| Режим агрегации | По режимам | Разные сценарии |
| Порядок работы | Параллельно / Последовательно | Гибкость |
| Возврат на доработку | Есть | Возможность исправить |
| Итерация этапа | Много | Возможность вернуться |
| Итерация процесса | Вычисляемое представление | Для UI |
| Выбор целевого этапа | Есть | Гибкость при возврате |
| Ответственный | Нет | — |
| Финальное решение | Нет | — |
| Ревизии документа | По флагу `processIterationEnabled` | Опционально |
| Автосогласование этапов | Есть | — |
| Итог | Определяется последним этапом | — |

### 3.4 Формирование итога

**Ключевая идея.** Итог процесса определяется решением **последнего этапа**. До последнего этапа процесс доходит только после успешного согласования всех предыдущих.

**Пример:**

```
Этап 1. Проверка → согласован
Этап 2. Согласование → согласован
Этап 3. Утверждение (последний) → согласован
    ↓
Процесс: Согласован
```

Если этап 3 отклонён:

```
Этап 3. Утверждение → отклонён
    ↓
Возврат на доработку
    ↓
Инициатор выбирает целевой этап (см. раздел 3.6)
    ↓
Новая итерация выбранного этапа
```

### 3.5 Поведение при отклонении

| Ситуация | Что происходит |
|---|---|
| Отклонение на любом этапе | Возврат на доработку |
| Инициатор выбирает целевой этап | Создаётся новая итерация |
| Целевой этап = текущий | Новая итерация текущего этапа |
| Целевой этап < текущий | Новая итерация целевого + сброс последующих |
| Целевой этап = 1 | Перезапуск всего маршрута |

**Важно.** Стандартный процесс **не имеет статуса «Отклонён» на уровне процесса**. Процесс завершается только в статусах Согласован, Согласован с замечаниями или Архивирован.

### 3.6 Выбор целевого этапа

**Условие применения:** работает всегда — независимо от `processIterationEnabled`.

**Как работает:**
1. Этап отклонён.
2. Процесс → `На доработке`.
3. Инициатор обрабатывает замечания.
4. Нажимает «Возобновить».
5. Если `allowedReturnStages` содержит > 1 этап → **модалка «На какой этап направить?»**.
6. Инициатор выбирает целевой этап.
7. Создаётся новая итерация выбранного этапа.

**Кто выбирает:** только инициатор.

**Когда:** только при возобновлении процесса.

**Пример:**

Исходная ситуация: Этап 1 ✅, Этап 2 ✅, Этап 3 ❌.

| Выбор | Что происходит |
|---|---|
| **Возврат на этап 3** | Этап 1 Iter 1 ✅, Этап 2 Iter 1 ✅, Этап 3 Iter 2 |
| **Возврат на этап 1** | Этап 1 Iter 2, Этап 2 Iter 2, Этап 3 Iter 2 |
| **Возврат на этап 2** | Этап 1 Iter 1 ✅, Этап 2 Iter 2, Этап 3 Iter 2 |

### 3.7 Логика создания итераций

> **При активации любого этапа:** если у этапа уже есть итерации — создать новую. Иначе — Iter 1.

**Работает одинаково для всех случаев:**
- Нормальный переход на следующий этап.
- Возврат на любой этап.

### 3.8 Вычисление «итерации процесса»

**Итерация процесса** — вычисляемое представление, не хранится физически.

**Формула:**
```
processIteration = max(stageIteration.iterationIdx)
```

**Зачем:** для группировки и отображения в листе согласования.

**Пример:**

```
Этап 1: Iter 1 ✅, Iter 2 ✅
Этап 2: Iter 1 ✅, Iter 2 (активный)
Этап 3: Iter 1, Iter 2 (ждёт)

processIteration = 2
```

### 3.9 Ревизии документа

**Условие:** `processIterationEnabled=true`.

**Что разрешено:**
- Инициатор создаёт новую ревизию.
- Создаётся новый процесс для новой ревизии.
- Оба процесса связаны через `documentAggregateId`.

**Что происходит:**
1. Инициатор решает, что замечания серьёзные.
2. Создаёт новую ревизию (`revisionLabel`).
3. Выбирает: прервать ли предыдущий процесс.
4. Создаётся новый процесс с новой ревизией.

**При `processIterationEnabled=false`:** ревизии запрещены.

### 3.10 Жизненный цикл

```
Draft
  ↓ StartProcess (инициатор)
InProgress
  ↓ все этапы пройдены
Approved | ApprovedWithComments
  ↓ (180 дней)
Archived

Ветки:
  InProgress → OnRework (этап отклонён)
  OnRework → InProgress (возврат на выбранный этап)
  InProgress | OnRework → Recalled
  Recalled → Draft | Archived
```

### 3.11 Бизнес-правила

| Правило | Значение |
|---|---|
| Лимит итераций | Отсутствует |
| Возврат на этап | Работает всегда |
| Выбор целевого этапа | Только инициатор, только при возобновлении |
| Возобновление | Только при всех обработанных замечаниях |
| Взятые в работу этапы | Не изменяются |
| ApproveWithComments | Замечания считаются несущественными |
| Ревизии | По флагу `processIterationEnabled` |

## 4. Единый процесс (UNIFIED)

### 4.1 Назначение

Процесс, в котором все этапы проходятся последовательно, а итоговое решение принимает ответственный.

### 4.2 Когда использовать

- Нужна одна точка ответственности за результат.
- Мнения участников важны, но не определяют итог.
- Маршрут согласовывает ответственный.
- Возврата на доработку не требуется.

### 4.3 Характеристики

| Свойство | Значение | Обоснование |
|---|---|---|
| Этапы | Несколько, последовательно | Все этапы проходятся |
| Участники этапа | Все параллельно | Решения фиксируются |
| Влияние решений участников | Нет | Итог определяет ответственный |
| Итерация этапа | Одна, невидимая | Не нужна пользователю |
| Ответственный | Обязателен | Точка ответственности |
| Ответственный как участник | **Возможно** | Может голосовать |
| Финальное решение | Обязательно | Определяет итог |
| Возврат на доработку | Нет | — |
| Возобновление | Нет | — |
| Срок финального решения | Нет | — |
| Ревизии документа | Не применимы | Нет возврата |
| Автосогласование этапов | Есть | — |
| Итог | Финальное решение ответственного | — |

### 4.4 Финальное решение

**Ключевая идея.** Ответственный принимает финальное решение после того, как все участники высказались.

**Что видит ответственный:**
- Все этапы маршрута.
- Все решения участников.
- Все замечания и комментарии.
- Рекомендации доп. согласующих.

**Возможные решения:**

| Решение | Итог процесса |
|---|---|
| Согласовать | Согласован |
| Согласовать с замечаниями | Согласован с замечаниями |
| Отклонить | Отклонён |

### 4.5 Ответственный как участник

**Ответственный может быть участником этапа.**

**Правила:**
- Ответственный может быть назначен на любой слот.
- Может голосовать на этапах.
- Финальное решение **не зависит** от его голосов.

**Пример:** ответственный проголосовал «Согласовать» на этапе, но финальное решение — «Отклонить». Допустимо.

### 4.6 Прохождение этапов

**Внутри этапа:**
- Все участники параллельно.
- Решения фиксируются, но не влияют на движение.
- Этап завершается, когда все приняли решение или истёк срок.

**Переход:**
- Этапы идут последовательно.
- Возврата на доработку нет.
- Отклонение участника не останавливает процесс.

### 4.7 Жизненный цикл

```
Draft
  ↓ SubmitRoute (инициатор)
PendingResponsibleApproval
  ↓ ApproveRoute (ответственный)
InProgress
  ↓ все этапы пройдены
AwaitingFinalDecision
  ↓ FinalDecision (ответственный)
Approved | ApprovedWithComments | Rejected
  ↓ (180 дней)
Archived

Ветки:
  PendingResponsibleApproval → Draft (RejectRoute)
  PendingResponsibleApproval → Recalled
  InProgress → Recalled
  Recalled → Draft | Archived
```

### 4.8 Бизнес-правила

| Правило | Значение |
|---|---|
| Ответственный | Обязателен |
| Ответственный как участник | Возможно |
| Финальное решение | Неизменяемо |
| Доп. согласующие на финале | Не назначаются |
| Срок финала | Нет |
| Возврат на доработку | Нет |
| Возобновление | Нет |
| Ревизии | Не применимы |
| Инициатор отзывает | До финального решения |

- Если оба — инициатор выбирает.

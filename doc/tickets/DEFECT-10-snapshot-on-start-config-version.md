# DEFECT-10 — Snapshot-on-Start: версия карты переходов фиксируется константой

> Найден при документировании кода (PR #17). Исправление — ветка `fix/defect-10-config-version`.
> Связанные тикеты: DEFECT-07 (итерации), DEFECT-14 (версионирование шаблонов).

## Статус

`Не начато`

## Контекст

ADR-003 требует, чтобы процесс навсегда запоминал версию карты переходов, по которой стартовал
(Snapshot-on-Start), — иначе публикация новой карты изменит поведение уже идущих согласований.
Поле `ProcessInstance.configVersion` для этого есть, движок ищет карту по
`(entityType, processType, version)`, но генератор маршрута записывает в поле константу `1`.
Пока в репозитории одна версия карты, дефект незаметен; при появлении второй версии процессы
будут исполняться по чужой карте (или падать с «нет конфигурации»).

## Дефект

```java
.configVersion(1)   // RouteGenerationService.buildProcess
```

Последствия:

1. Процесс не «запоминает» карту: поле всегда `1`, независимо от того, какая версия была
   опубликована и использована при генерации. Snapshot-on-Start не реализован.
2. При публикации карты `version = 2` для того же `processType` новые процессы получат
   `configVersion = 1` и будут исполняться по старой карте — либо, если старая карта удалена
   (Fork & Drain этого не допускает, но если её перевести в `ARCHIVED` и почистить), упадут с
   `IllegalStateException` «No StateMachineConfig for entityType=PROCESS...».
3. `TransitionMapValidator` при старте проверяет все `PUBLISHED`-карты, поэтому ошибка
   проявится не на старте, а в момент первого перехода.

## Явно не входит (Out of scope)

- Механизм публикации карт через API (`POST /configs` в контракте, в коде отсутствует).
- Fork & Drain для карт (инкремент `active_process_count` при старте процесса и запрет удаления
  версии) — отдельная задача, см. DEFECT-07/14.

## Технические требования

1. При создании процесса определять актуальную версию карты для пары
   (`entityType = PROCESS`, `processType`) среди карт в статусе `PUBLISHED` и записывать её
   номер в `configVersion`. Если опубликованных карт несколько версий — брать максимальную
   версию (после ADR-003 старые остаются `PUBLISHED` до завершения процессов, поэтому «первая
   найденная» неверна).
2. Если опубликованной карты нет — не создавать процесс: бросить доменное исключение с понятным
   текстом (см. DEFECT-06 про маппинг в 4xx), а не полагаться на константу.
3. Проверить, что `ProcessService.startProcess`/`resume`/`recall` читают карту именно по версии
   процесса (сейчас так) и что версия не перезаписывается после старта.
4. Учесть карты `STAGE` и `TEMPLATE`: для этапов используется та же версия, что у процесса
   (`AssignStageTasksAction`, `ActivateTargetStageAction` ищут конфиг по
   `process.getProcessType()` и `process.getConfigVersion()`) — значит версия должна быть
   согласована между картами PROCESS и STAGE. Если это не так, зафиксировать расхождение в
   отчёте и вынести отдельной задачей (возможно, версии карт PROCESS и STAGE нужно публиковать
   парой).
5. Заодно зафиксировать в `active_process_count` факт старта процесса по версии (Fork & Drain),
   если это укладывается в объём; иначе — явно оставить в out of scope и отметить в PR.

## Критерии приёмки

1. Интеграционный тест: при двух опубликованных картах (`version = 1` и `version = 2`) новый
   процесс получает `configVersion = 2` и исполняется по карте версии 2.
2. Тест: процесс, созданный до публикации версии 2, продолжает исполняться по версии 1 —
   снапшот действительно зафиксирован.
3. Тест: при отсутствии `PUBLISHED`-карты создание процесса возвращает доменную ошибку (4xx),
   а не создаёт процесс с несуществующей версией.
4. Обратный поиск по коду не находит литерала `configVersion(1)`.
5. `./gradlew build` зелёный; существующие тесты генерации маршрута обновлены осознанно.

## Тестирование

## Открытые вопросы

1. **Как публикуются карты:** через API/миграции/вручную? От этого зависит, где искать
   «последнюю опубликованную» версию и нужно ли вообще поддерживать несколько `PUBLISHED`
   одновременно.
2. Нужно ли **фиксировать конфиг целиком** (сериализованная модель), а не только версию? ADR-003
   говорит «Snapshot-on-Start» в смысле версии; если карту можно отредактировать на месте,
   одной ссылки на версию недостаточно.
3. Должны ли версии карт `PROCESS` и `STAGE` публиковаться согласованно (парой), если они
   связаны по `configVersion`?
